# V1.18 河牌决策教学化 + 策略分区热力图

> 版本令牌：`SOLVER_REV = 'v1.18'`（仅隔离缓存，db schema 与已录数据零改动）
> 场景：`BTN Kc4d / 牌面 Kh7s2cTsAc / 河牌 BB bet 39.1BB`；用户给定口径 GTO 95% 跟 / 5% 弃、对下注范围权益约 30%。

## 1. 需求与背景

用户要求两件事：
1. **教学化河牌分析**：用教学语言解释价值/诈唬组合拆解、抓诈赔率、为何 GTO 高频跟注、面对 TAG/LAG 如何调整频率。落到结果页「均衡输出」卡片。
2. **升级范围热力图**：按 hero 具体组合标注 call/raise/fold、混合标频率、纯策略标动作、完整花色、简洁图例与分组。落到「范围热力图」卡片。

## 2. 数据核对（真实求解，非硬编码）

用 `parseHH → deriveState → rangesForDecision → solveCore` 实测牌谱，用户给的三个数字全部对上：

| 项 | 用户给定 | 代码实测 | 结论 |
|---|---|---|---|
| 决策点 | 河牌面对 39.1BB | index=9 / RIVER / toCall=39.1 / pot=97.5 | ✓ |
| GTO 频率 | 95% 跟 / 5% 弃 | focus 跟 94.6% / 弃 5.4%（范围平均跟 40.2%） | ✓ 用户说的是**你这手牌的条件策略** |
| 权益 | 约 30% | focus 对下注范围 31.6% | ✓ |
| 抓诈赔率 | — | 39.1 / (97.5+39.1) = 28.6%，31.6% > 28.6% → call EV +4.04BB | ✓ |

**一个反直觉的真实发现**：用户举例的 QJs 在这副牌面是**顶级价值**（A-K-T 牌面下 QJ 组成 A-K-Q-J-T 顺子，eq 0.993），不是诈唬；真正的诈唬区是 JJ/QQ/QTs/JTs/99/88（eq 0.39~0.52）。因此教学分析**基于真实权益排序动态生成**，不硬编码组合清单，并在文字中讲清拆解逻辑（见 §3.1）。

## 3. 实现契约

### 3.1 教学数据 `lesson`（`js/solver-core.js: buildRiverLesson`）

仅在**河牌 + 面对下注**时生成（`board.length === 5 && facing > 0`），翻前/翻牌返回 `null`。字段：

- 赔率三件套：`pot`、`bet`、`needPct = bet/(pot+bet)`（抓诈门槛）、`mdf = pot/(pot+bet)`（最小防守频率，二者和为 1）。
- 权益：`heroEquity`（**对 Villain 下注范围的权益**，见 §4 的 V1.18.1 修复）、`heroEquityAllRange`（对 Villain 全范围权益，仅用于对比说明）、`bluffCatchOk`。
- 组合拆解：把 Villain 下注范围按**河牌穷举精确权益**（`villainEq`）排序，价值区取前 `betValueFrac`、诈唬区取后 `betBluffFrac`（跨街衰减后）；每类手牌聚合 `label/combos/eq/examples`（完整花色最多 4 个）。字段 `value[]`、`bluff[]`、`valueCombos`、`bluffCombos`、`polarization`、`streetSteps`。
- 组合排序按真实权益，故 QJs 自动落入价值区且文字解释"这是顺子"。

### 3.2 策略热力图 `heatmap.strategy`（`strategyHeatFor`）

13×13 每格输出三路频率 `fold/call/raise` + 主策略 `main` + 混合标记 `mix`（最高频 <0.9 为混合）+ 组合数 `n` + 完整花色 `cards[]`（最多 4 个）。填格逻辑：FOLD→fold、CALL/CHECK→call、BET/RAISE/ALLIN→raise；对同类别所有组合取平均。

- **GTO 档** `strategy.hero` 用均衡节点策略；**剥削档**同时保留 `strategy.exploit`（剥削节点）与 `strategy.gto`（均衡节点），切 tab 时与主表同源。
- 该河牌决策点无加注动作（面对 39.1BB 后手不足、桶策略未展开 raise），实测分布 63 格弃 / 53 格跟 / 10 个混合策略格——无 R 是物理结果，非 bug。

### 3.3 UI（`js/app.js` + `js/charts.js` + `styles.css`）

- 新增 `riverLessonHtml(r)`：四段教学（① 局面与赔率 ② 为什么 GTO 高频跟注 MDF ③ 对手下注范围拆解 ④ 面对 TAG/LAG 频率调整），数据全部来自本次求解。GTO 档给通用方向 + 河牌跨街衰减提示；剥削档按极化度给具体判断。
- 教学块嵌入结果页均衡输出卡片「你的手牌」行之后。
- 新增 `renderStrategyHeatmap(container, grid, opts)`：按 `main` 三色（fold 灰蓝 / call 蓝 / raise 红），混合格标频率数字、纯策略标 F/C/R 字母，你手牌聚焦格加蓝框；图例三色说明 + 分组说明；格子 title 含完整花色与三路频率。Hero 用策略分区图，Villain 保留原热力图（它无"面对自己下注"的策略语义）。
- CSS 新增 `.river-lesson/.lesson-sec/.lesson-combo/.lesson-tag` 与 `.strat-grid/.strat-legend/.cell` 等。

## 4. V1.18.1 关键修复：权益口径错用（本次核查发现并修正）

**问题**：初版 `lesson.heroEquity` 取 `focus.equityVsVillainRange`（对 Villain **全范围**权益），但抓诈门槛必须对比对 **Villain 实际下注范围**的权益 `focus.conditional.eqCall`。GTO 档下注范围=全范围，两者巧合相等（31.6%），未暴露；剥削档下注范围被极化收窄后 eqCall 暴跌，导致教学文案误报"权益达标应跟注"。

**实测对比（Kc4d 河牌）**：

| 档位 | 全范围权益 | 下注范围权益(eqCall) | 门槛 | 实际 call EV | 修复前教学结论 | 修复后 |
|---|---|---|---|---|---|---|
| GTO | 31.6% | 31.6% | 28.6% | +4.04 | 正确 | 正确 |
| TAG | 35.3% | **2.6%** | 28.6% | −35.51 | ❌ 误报达标 | ✅ 弃牌正解 |
| LAG | 35.2% | **23.5%** | 28.6% | −7.03 | ❌ 误报达标 | ✅ 弃牌正解 |

**修复**：`buildRiverLesson` 的 `heroEquity` 优先取 `conditional.eqCall`，回退全范围值；新增 `heroEquityAllRange` 供文案对比。教学文案改为"你对**下注范围**的权益 X% vs 门槛"，并在两口径差异 >3% 时补一句"全范围权益虽有 Y%，但对手下注范围已收窄/极化，不能用来抓诈"。这正解释了用户要的"面对 TAG 更紧范围权益更小"——TAG 下注范围价值占比极高（诈唬仅 1.25%），eqCall 掉到 2.6%。

## 6. 已知边界

- 价值/诈唬区按 `betValueFrac/betBluffFrac` 对下注范围做**比例切分**，非对手真实策略的精确重建；教学用"权益高=价值、权益低=诈唬"是合理近似。
- 热力图策略是**桶级策略**（10 档权益桶）按组合类别聚合，同类别内的花色差异不区分（以 13×13 聚合 + tooltip 花色示例呈现）。
- 河牌权益为穷举精确值，无采样误差；跨街极化继承 V1.17 口径（按街数派生修正，非真三街展开树）。
